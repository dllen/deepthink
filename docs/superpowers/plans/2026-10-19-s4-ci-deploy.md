# S4 CI 与部署可靠性 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** PR 不再触发部署；部署有并发/超时保护；部署后自动冒烟并能在"200 假成功"下发现资源缺失。

**Architecture:** 在现有 `deploy.yml` 上加事件条件、并发、超时、fork PR 降级与部署后冒烟；生产入口固定为 `deepthink.global`。

## Task 2: 部署后冒烟

**Files:**
- Modify: `.github/workflows/deploy.yml`

- [ ] **Step 1: 在 Deploy 之后加冒烟步骤**

```yaml
    - name: Smoke test production
      if: github.event_name == 'workflow_dispatch' || (github.event_name == 'push' && github.ref == 'refs/heads/main')
      run: |
        set -euo pipefail
        EXPECTED=$(grep -o 'assets/index-[^"]*\.js' dist/index.html | head -1)
        if [ -z "$EXPECTED" ]; then
          echo "::error::could not find built asset in dist/index.html"
          exit 1
        fi
        echo "Expected asset: $EXPECTED"

        BASE="https://deepthink.global"
        OK=0
        for attempt in 1 2 3 4 5 6; do
          code=$(curl -sS -o /tmp/index.html -w '%{http_code}' "$BASE/" || true)
          ctype=$(curl -sSI "$BASE/" | tr -d '\r' | awk -F': ' 'tolower($1)=="content-type"{print $2}' | head -1)
          actual=$(grep -o 'assets/index-[^"]*\.js' /tmp/index.html | head -1 || true)
          echo "attempt $attempt: status=$code content-type=$ctype asset=$actual"
          if [ "$code" = "200" ] && echo "$ctype" | grep -qi 'text/html' && [ "$actual" = "$EXPECTED" ]; then
            OK=1
            break
          fi
          sleep 10
        done
        if [ "$OK" != "1" ]; then
          echo "::error::production index did not match the deployed build"
          exit 1
        fi

        acode=$(curl -sS -o /tmp/app.js -w '%{http_code}' "$BASE/$EXPECTED")
        atype=$(curl -sSI "$BASE/$EXPECTED" | tr -d '\r' | awk -F': ' 'tolower($1)=="content-type"{print $2}' | head -1)
        echo "asset: status=$acode content-type=$atype"
        if [ "$acode" != "200" ] || ! echo "$atype" | grep -qi 'javascript'; then
          echo "::error::deployed asset is missing or wrong content-type"
          exit 1
        fi

        lcode=$(curl -sS -o /dev/null -w '%{http_code}' "$BASE/logo.svg")
        ltype=$(curl -sSI "$BASE/logo.svg" | tr -d '\r' | awk -F': ' 'tolower($1)=="content-type"{print $2}' | head -1)
        echo "logo: status=$lcode content-type=$ltype"
        if [ "$lcode" != "200" ] || ! echo "$ltype" | grep -qi 'image/svg'; then
          echo "::error::logo.svg missing or wrong content-type"
          exit 1
        fi

        echo "Production smoke passed"
```

- [ ] **Step 2: 本地预演冒烟脚本**

把上面的脚本保存到 `/tmp/smoke.sh`，用当前生产（旧 workflow 版本）运行一次：

Expected：输出 `Production smoke passed`（旧部署 asset 可能与本地 dist 不同，此时用生产实际 asset 做临时验证；正式以 CI 内构建产物为准）。

## Task 3: 文档

**Files:**
- Modify: `README.md`、`dev.md`、`CLAUDE.md`、`AGENTS.md`

- [ ] **Step 1: README 部署章节**

补：

- 生产入口固定为 `https://deepthink.global`；GitHub Pages 项目地址 `dllen.github.io/deepthink/` 不支持（绝对路径 + 未设 `base`）。
- PR 会跑 `test:data` / `check:data` / `build`，但**不会部署**；只有 push `main`（或手动 `workflow_dispatch`）才部署。
- 部署后自动冒烟：校验首页 200 + content-type、asset 与构建一致、`/logo.svg`；失败会让 workflow 变红。
- 手动回滚：`git revert <commit> && git push`；不建议直接改 `gh-pages`。

- [ ] **Step 2: dev.md / CLAUDE.md / AGENTS.md**

同步"PR 不部署、workflow_dispatch 手动发布、回滚方式、冒烟内容"。
